# Feature Specification: 设置页分类聚合重构

**Created**: 2026-08-15
**Status**: Draft
**Input**: User description: "对设置选项的内容进行聚合，现在设置选项太乱了，几乎所有的设置都在一级菜单里，不简洁也不好用"

## Overview

当前设置页约 40 个设置项全部平铺在一级菜单（浏览 9 项、下载 9 项、屏蔽 2 项、网络 4 项、中继 9 项、其他 4 项、账户 2 项），页面过长、查找困难。本特性将设置项按语义聚合为 7 个分类，一级页面只保留分类入口，点击进入独立的二级设置子页，所有既有功能与交互保持不变。

## User Scenarios & Testing

### User Story 1 - 分类聚合的设置首页 (Priority: P1)

用户打开设置页，看到的不再是几十项平铺的长列表，而是 7 个语义化分类入口（浏览与显示、下载与元数据、屏蔽与过滤、网络、中继服务器与同步、通用、账户），点击分类进入对应二级子页，子页返回键回到设置首页。

**Why this priority**: 这是本特性的核心价值——降低认知负担、缩短查找路径。仅此一项即可独立交付可用成果。

**Independent Test**: 打开设置页即可验证：首页只显示分类入口；逐一点击 7 个分类均可进入子页并返回。

**Acceptance Scenarios**:

1. **Given** 用户位于主页 Tabs 的设置 Tab，**When** 页面展示，**Then** 一级菜单仅呈现 7 个分类入口行，无散落的单项设置
2. **Given** 设置首页，**When** 点击"网络"分类，**Then** 进入网络设置子页，展示认证方式/API 方式/图床/自定义图床 4 项
3. **Given** 任意二级设置子页，**When** 点击系统返回，**Then** 回到设置首页且路由栈正常

---

### User Story 2 - 既有设置项功能无损平移 (Priority: P1)

每个分类子页中的设置项保持原有交互与行为：选择类（质量/线程数/网络方式等）弹 Picker 并即时生效；开关类即时写入并触发对应副作用（如 R18 榜单过滤、防社死遮罩）；跳转类（下载管理/屏蔽管理/历史记录/文件名模板/EXIF 标签管理/关于等）正常进入三级页面；中继组的服务器地址输入、注册/登录、数据同步开关、立即同步、导出同步账号、后端自检、注销账号等完整可用。

**Why this priority**: 功能回归零容忍是重构的前提；与 US1 同为 P1，因为只有分类骨架而功能受损不可接受。

**Independent Test**: 在每个子页逐项操作原设置项，对照重构前行为逐项验证（修改生效、持久化、跳转、弹窗均一致）。

**Acceptance Scenarios**:

1. **Given** 网络子页，**When** 将 API 方式切换为"中继"，**Then** 设置即时持久化，后续 API 请求走中继链路（与重构前一致）
2. **Given** 中继服务器与同步子页，**When** 点击"后端自检"，**Then** 弹出自检覆盖层，六项状态实时刷新（保持最近修复的行为）
3. **Given** 下载与元数据子页，**When** 修改"文件名模板"跳转并返回，**Then** 模板配置正常保存
4. **Given** 任意子页修改设置后杀进程重进，**When** 再次进入该子页，**Then** 显示修改后的值（持久化不受影响）

---

### User Story 3 - 分类入口摘要预览 (Priority: P3)

设置首页的分类入口行右侧显示该分类关键当前值摘要（如"网络"显示"认证:标准 · API:中继"，"下载与元数据"显示"原图 · 3 线程"），帮助用户不进入子页即可感知当前配置。

**Why this priority**: 体验增强，非必需；缺失不影响分类聚合的核心价值。

**Independent Test**: 在子页修改某项后返回首页，对应分类摘要文字同步更新。

**Acceptance Scenarios**:

1. **Given** 设置首页，**When** 查看"网络"分类行，**Then** 右侧摘要与当前认证/API 方式一致
2. **Given** 在子页修改了对应设置，**When** 返回设置首页，**Then** 摘要文字即时刷新

---

### Edge Cases

- 二级子页路由参数为空时正常渲染（不依赖传参，状态全部来自既有 Store）。
- 子页内触发覆盖层弹窗（后端自检/清理缓存确认等）后返回，弹窗状态不残留。
- 路由栈：设置首页（Tab 内）→ 二级子页 → 三级页（如下载管理），逐层返回不跳页、不丢栈。
- 登录态相关：账户子页"退出登录"后清栈回登录页，与既有行为一致。

## Requirements

### Functional Requirements

- **FR-001**: 设置首页 MUST 仅展示 7 个分类入口：浏览与显示、下载与元数据、屏蔽与过滤、网络、中继服务器与同步、通用、账户
- **FR-002**: 每个分类 MUST 对应一个独立路由子页（注册进 main_pages.json），通过 router.pushUrl 进入
- **FR-003**: 全部既有设置项 MUST 无删减地平移到对应分类子页，交互方式（Picker/开关/跳转/输入框/弹窗）与副作用保持不变
- **FR-004**: 设置项的读取与写入 MUST 继续走既有 UserSettingStore/相关 Store，持久化格式与键不变（用户升级后配置不丢）
- **FR-005**: 二级子页 MUST 有标题栏与返回能力，返回到设置首页
- **FR-006**: 分类入口 SHOULD 显示关键当前值摘要，且在子页修改返回后自动刷新
- **FR-007**: 既有三级页面（下载管理、屏蔽管理、历史记录、文件名模板、EXIF 标签管理、关于、我的收藏等）MUST 从对应分类子页正常进入，路由注册不变

### Key Entities

- **设置分类（Category）**：名称、包含的设置项集合、摘要文字来源；共 7 个固定分类
- **设置项（Setting Item）**：归属分类、展示形态（选择/开关/跳转/输入）、当前值——均沿用既有 AppSettings 模型，无数据结构变更

## Success Criteria

### Measurable Outcomes

- **SC-001**: 设置首页首屏可见项从约 40 项降至 7 个分类入口（减少 >80%）
- **SC-002**: 用户到达任意设置项的点击次数 ≤ 2 次（首页→分类→项）
- **SC-003**: 重构后全部既有设置项功能验证通过率 100%（无功能丢失/行为变化）
- **SC-004**: 升级后既有用户配置 100% 保留（无重置、无丢项）

## Assumptions

- 分类划分沿用现有 SectionHeader 语义（浏览→浏览与显示、下载→下载与元数据、其他→通用、屏蔽与过滤/网络/中继/账户不变），用户对现有分组语义已熟悉
- 二级子页采用独立路由页面（用户已确认），风格与既有 DownloadPage 等子页一致
- 首页分类摘要为 P3 增强，如实现成本异常可裁剪而不影响主体验收
- 不新增/删除任何设置项本身，不做设置项语义调整

## Open Questions

- 无（分类划分沿用既有分组语义、子页形态已确认为独立路由页面、摘要为可选增强）
