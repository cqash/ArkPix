# Feature Specification: 验证问题修复第一轮（verification-fixes-round1）

**Created**: 2026-07-27  
**Status**: Draft  
**Input**: User description: "上一轮功能（history-search-comments）人工验证发现的 11 个问题：下载重试单个而非全部、历史记录重复、画师搜索不生效且无历史、ID直达无历史、空历史导出无提示、详情页按钮截断、评论发表 500、登录后返回退到登录页、tag合并输入无补全、下载进度不自动更新、合并对话框遮罩挡住交互"

## Overview

修复上一轮功能交付后人工验证发现的 11 个问题：9 个 bug（下载重试/历史重复/画师搜索/空历史导出提示/按钮截断/评论 500/登录返回栈/下载进度刷新/合并对话框遮挡）+ 1 个搜索历史记录范围补全 + 1 个增强（tag 合并对话框输入补全）。目标是让已交付功能达到真实可用状态。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 评论发表修复（500 错误）(Priority: P1)

用户在评论页主楼输入评论并发送，评论成功发布并出现在列表中。当前发送主楼评论必现服务器 500 错误，发表功能完全不可用，需定位（请求字段/编码/响应解析）并修复；回复楼发送路径同样验证。

**Why this priority**: 核心功能完全不可用，最高严重度。

**Independent Test**: 任意作品评论页发送主楼评论成功；对某评论发送回复成功。

**Acceptance Scenarios**:

1. **Given** 已登录且网络正常，**When** 在评论页输入文字（≤140 字）发送主楼评论，**Then** 发送成功，新评论出现在列表，无 500 错误
2. **Given** 评论页，**When** 对某条评论发送回复，**Then** 回复发送成功并出现在其回复楼
3. **Given** 服务端确实拒绝（如风控），**When** 发送失败，**Then** toast 错误提示且输入内容不丢失

---

### User Story 2 - 画师搜索修复与搜索历史全量记录 (Priority: P1)

用户在搜索结果页"画师"Tab 看到正常的用户列表（头像正常加载、显示名称与账号，而非灰色头像和"@"）；插画词搜索、画师 Tab 搜索、PID/UID 数字直达均写入搜索历史（带类型标识）；历史记录页搜索历史 Tab 点击条目时按其类型回放（插画词→插画搜索结果、画师词→画师 Tab 结果、PID→详情、UID→用户主页）。

**Why this priority**: 画师搜索当前完全不可用（数据解析错误），且搜索历史缺失违背已交付需求。

**Independent Test**: 作者名搜索→画师 Tab 显示正常用户列表；四类搜索行为各执行一次→历史页搜索 Tab 全部可见且点击回放正确。

**Acceptance Scenarios**:

1. **Given** 输入作者名提交并切到画师 Tab，**When** 列表渲染，**Then** 每项显示真实头像、名称、账号
2. **Given** 画师 Tab 有结果，**When** 上拉到底，**Then** 正常分页加载
3. **Given** 分别执行：插画词搜索、画师 Tab 搜索、PID 直达、UID 直达，**When** 打开历史记录页搜索历史 Tab，**Then** 四类记录均存在且有可区分的类型标识
4. **Given** 搜索历史中有各类型条目，**When** 逐一点击，**Then** 按类型回放：插画词→插画搜索、画师词→画师 Tab、PID→作品详情、UID→用户主页
5. **Given** 画师 Tab 搜索无结果，**When** 列表为空，**Then** 显示空态而非异常行

---

### User Story 3 - 历史记录按作品合并展示 (Priority: P1)

历史记录页浏览历史 Tab 中同一作品只出现一次（展示最新一条），不再出现重复条目。不清理数据库中的存量重复行（用户明确选择），仅在查询/展示层按作品 ID 合并；新写入沿用已实现的 DELETE+INSERT 去重。

**Why this priority**: 列表重复直接影响主路径体验；用户确认是高频可见问题。

**Independent Test**: 同一作品多次浏览（含更新前产生的存量重复数据）→ 历史页该作品只显示一次且为最新时间。

**Acceptance Scenarios**:

1. **Given** DB 中同一 illust_id 存在多条历史（含存量），**When** 打开历史页浏览 Tab，**Then** 该作品只显示最新一条
2. **Given** 某作品曾浏览过，**When** 再次浏览后回到历史页，**Then** 该作品仍只一条且排在最前
3. **Given** 导出历史（JSON/PID），**When** 检查导出内容，**Then** 与展示一致，同一作品只有最新一条

---

### User Story 4 - 登录后返回栈修复 (Priority: P1)

用户刚完成登录进入首页后，按系统返回键直接退出应用（或按平台默认行为），不会退回登录页。登录成功跳转必须使用替换式导航（替换掉登录页），而非压栈。

**Why this priority**: 每次新登录必现的导航错误，体感严重。

**Independent Test**: 退出登录 → 重新登录 → 进首页按返回 → 不退回登录页。

**Acceptance Scenarios**:

1. **Given** 刚登录成功进入首页，**When** 按系统返回键，**Then** 不回到登录页（退出应用或平台默认行为）
2. **Given** 从 Splash 自动登录进入首页，**When** 按返回键，**Then** 行为同样正确（无回归）

---

### User Story 5 - 下载管理修复（重试全部 + 进度实时刷新）(Priority: P2)

下载管理页点击"重试失败"时重试**全部**失败任务（当前只重试了一个）；下载进行中页面进度自动刷新（当前必须退出重进才更新），包括进度百分比、状态变化（下载中→完成/失败）实时反映。

**Why this priority**: 功能存在但行为明显错误；不影响主浏览路径。

**Independent Test**: 制造 2+ 失败任务点重试→全部重新下载；下载中大图时停留页面观察进度条自动推进直至完成。

**Acceptance Scenarios**:

1. **Given** 下载管理有 3 个失败任务，**When** 点击重试失败，**Then** 3 个任务全部重新进入下载流程
2. **Given** 有任务正在下载，**When** 停留在下载管理页，**Then** 进度/状态自动更新，无需退出重进
3. **Given** 任务从下载中变为完成或失败，**When** 停留在页面，**Then** 状态变更自动反映

---

### User Story 6 - 详情页操作区重设计与弹窗修复 (Priority: P1)

详情页操作区重新设计：移除原信息行内的按钮区，改为**右下角两个悬浮按钮（FAB）**——收藏 FAB 与下载 FAB；下载 FAB 点按保存当前页，**长按弹出菜单含"下载全部"**（仅多页作品显示）。"查看评论"从按钮区移出，改为 **tag 云与"相关作品"之间的居中文字按钮**（字号小、不抢眼）。同时修复：手动合并标签对话框（MergeDialogOverlay）的输入框/取消/确认按钮被遮罩挡住无法交互（移除 hitTestBehavior(Block)，改用 .onClick 消费点击方案）；历史为空时点导出显示"暂无历史记录"提示。

**Why this priority**: 操作区是详情页主交互路径，当前文字截断且重设计已明确；合并对话框不可交互导致合并功能不可用。

**Independent Test**: 详情页两个 FAB 正常工作（收藏/保存/长按下载全部）；tag 区下方可见小号"查看评论"文字按钮并可点击进评论页；合并对话框全部控件可交互。

**Acceptance Scenarios**:

1. **Given** 打开任意作品详情页，**When** 查看页面，**Then** 右下角显示收藏与下载两个悬浮按钮，原信息行按钮区不再显示
2. **Given** 单页作品，**When** 点按下载 FAB，**Then** 保存当前页；**When** 长按下载 FAB，**Then** 不出现"下载全部"菜单（或直接保存）
3. **Given** 多页作品，**When** 长按下载 FAB，**Then** 弹出菜单含"保存当前页/下载全部"
4. **Given** 打开详情页，**When** 查看 tag 云与"相关作品"之间区域，**Then** 有居中的小号"查看评论"文字按钮；点击进评论页
5. **Given** 已收藏作品，**When** 查看收藏 FAB，**Then** 显示已收藏态（红心），点按取消收藏——行为与原按钮一致
6. **Given** tag 长按选择"备注中合并"，**When** 弹出合并对话框，**Then** 输入框可聚焦输入、取消/确认按钮可点击；点击遮罩关闭对话框（防穿透保持）
7. **Given** 浏览历史为空，**When** 点击导出，**Then** 出现"暂无历史记录"提示且不弹保存选择器
8. **Given** 防社死模式下的 R18 详情页，**When** 查看 FAB，**Then** FAB 不被图片遮罩遮挡，功能正常

---

### User Story 7 - tag 合并对话框输入补全 (Priority: P2)

手动合并标签对话框中输入主 tag 名时，根据已输入的首字/前几个字实时弹出补全建议。补全来源按优先级：**(1) 本地已存储的合并 tag 记录**（exifMergedTags 规则中的 mainTag/fromTags）与 **(2) 当前作品的 tag 列表**——两者为优先来源，即时匹配展示；**仅当本地来源无匹配且输入停顿超过防抖时长时**，才调用 Pixiv 自动补全 API（项目已有 `getAutoComplete` /v2/search/autocomplete，未接线）提供联想词。用户点选建议项即填入输入框。输入为空时不显示建议、不请求 API。

**Why this priority**: 增强项，提升合并规则录入效率与准确性（主 tag 名输错会导致规则失效）。

**Independent Test**: 输入已有合并规则中某 mainTag 的前两个字→建议区优先出现该 tag；输入当前作品 tag 前缀→出现本作品 tag；输入两者都无匹配的词→防抖后出现 API 联想词。

**Acceptance Scenarios**:

1. **Given** 合并对话框打开，**When** 输入已存合并规则中某 tag 的前 1-3 个字，**Then** 建议区优先显示该本地合并 tag
2. **Given** 输入当前作品已有 tag 的前缀，**When** 查看建议区，**Then** 显示匹配的本作品 tag（与本地合并 tag 同为优先来源，去重展示）
3. **Given** 输入在两类本地来源均无匹配，**When** 停止输入超过防抖时长，**Then** 显示来自 Pixiv 补全 API 的联想词
4. **Given** 本地来源已有匹配，**When** 输入过程中，**Then** 不发起 API 请求
5. **Given** 建议区有内容，**When** 点击某建议项，**Then** 该项填入输入框，建议区收起
6. **Given** 输入为空，**When** 查看对话框，**Then** 不显示建议区、不发起 API 请求
7. **Given** API 请求失败或超时，**When** 输入过程中，**Then** 不影响本地来源建议展示，不报错打断

---

### Edge Cases

- 评论 500 的根因若为服务端字段校验（如空 parent_comment_id 被发送），修复后需验证主楼/回复楼两条路径
- 画师搜索分页 next_url 为空时停止加载
- 搜索历史回放画师词时若搜索结果页无 Tab 状态记忆，默认定位到画师 Tab
- 下载进度刷新频率过高导致卡顿：采用合理刷新间隔/事件驱动
- 重试全部时部分任务元信息缺失：跳过并 toast 说明跳过数量
- 登录页在某些流程下被 replaceUrl 后，从设置页"退出登录"进入登录页再登录，返回栈同样正确
- 合并对话框建议列表：本地两类来源（合并规则记录、本作品 tag）之间去重；本地有匹配时不请求 API
- FAB 与详情页现有交互的冲突：防社死遮罩揭示、图片长按菜单、EXIF 弹层/合并审查弹窗弹出时 FAB 的层级与可用性
- FAB 长按菜单遵循弹窗约定（bindContextMenu 或 AlertDialog，不用 ActionSheet）

## Requirements *(mandatory)*

### Functional Requirements

**评论修复**
- **FR-101**: 主楼评论发表 MUST 成功（修复 500 错误），回复楼发表 MUST 同样验证通过
- **FR-102**: 发送失败 MUST 保留输入内容并 toast 提示（保持既有行为）

**搜索修复与历史**
- **FR-201**: 画师 Tab 用户列表 MUST 正确解析并展示头像、名称、账号
- **FR-202**: 插画词搜索、画师 Tab 搜索、PID 直达、UID 直达 MUST 全部写入搜索历史（带类型标识）
- **FR-203**: 历史页搜索历史条目点击 MUST 按类型回放到对应目标（插画搜索/画师 Tab/详情页/用户主页）

**历史合并**
- **FR-301**: 浏览历史展示与导出 MUST 按 illust_id 合并，仅保留最新一条；MUST NOT 清理 DB 存量重复行

**导航修复**
- **FR-401**: 登录成功跳转首页 MUST 使用替换式导航，返回键不退回登录页

**下载管理**
- **FR-501**: "重试失败" MUST 重试全部失败任务（元信息缺失的跳过并提示数量）
- **FR-502**: 下载管理页 MUST 实时刷新任务进度与状态，无需退出重进

**详情页与弹窗**
- **FR-601**: 详情页操作区改为右下角双 FAB（收藏 + 下载）：收藏 FAB 点按收藏/取消（含已收藏态展示）；下载 FAB 点按保存当前页，长按弹菜单（多页含"下载全部"）；原信息行按钮区移除
- **FR-602**: "查看评论"改为 tag 云与相关作品之间的居中小号文字按钮
- **FR-603**: MergeDialogOverlay MUST 移除 hitTestBehavior(Block)，改用 .onClick(()=>{}) 防穿透方案，输入框与按钮恢复可交互
- **FR-604**: 空历史导出 MUST 提示"暂无历史记录"

**输入补全**
- **FR-701**: 合并对话框输入 MUST 实时显示补全建议，来源优先级：本地已存合并 tag 记录（exifMergedTags 的 mainTag/fromTags）与当前作品 tag 列表（两者优先、即时匹配、去重展示）；仅本地无匹配且输入停顿超过防抖时长时才调用 Pixiv 自动补全 API（/v2/search/autocomplete）
- **FR-702**: 点选建议 MUST 填入输入框；输入为空 MUST 不请求不显示；本地有匹配 MUST 不发起 API 请求

### Key Entities

- **搜索历史条目**（扩展）：keyword、search_type（新增取值：illust/user/pid/uid）、timestamp——利用现有 search_history 表 search_type 列（原为硬编码 'illust'）
- **下载任务**：现有 download_tasks 表状态机（downloading/completed/failed）
- **自动补全项**：Pixiv autocomplete 响应的联想词列表（tags 名称）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 主楼评论发送成功率 100%（排除服务端风控拒绝），0 次 500 错误
- **SC-002**: 画师搜索列表头像/名称/账号渲染正确率 100%，无"@"占位行
- **SC-003**: 四类搜索行为的历史记录覆盖率 100%，点击回放正确率 100%
- **SC-004**: 浏览历史页同一作品出现次数 ≤1
- **SC-005**: 登录后按返回键退回登录页发生次数为 0
- **SC-006**: 下载管理页进度刷新延迟 ≤2 秒感知，重试失败覆盖全部失败任务
- **SC-007**: 合并对话框全部控件可交互，输入补全建议 500ms 内出现（本地匹配即时，API 联想防抖后）

## Assumptions

- 历史合并不动存量 DB 数据（用户明确选择），仅查询/展示/导出层合并
- 搜索历史回放画师词时定位到结果页画师 Tab（结果页需支持初始 Tab 参数或等效机制）
- 数字直达写入搜索历史的 keyword 为数字原文，类型 pid/uid
- 评论 500 根因待定位（候选：请求字段多余/缺失、响应体解析、parent_comment_id 处理），修复以实测通过为准
- 登录后返回行为的目标：退回系统桌面（平台默认），不做"再按一次退出"双击确认
- 补全建议 UI 复用合并对话框内联区域（输入框下方列表），不新增弹窗组件
- #9 增强的 API 失败不影响本地 tag 匹配

## Open Questions

- 无（全部关键决策已澄清：历史全量记录/仅新记录去重/按钮两行排列）
