# Feature Specification: 多端流转与鸿蒙设备间数据同步（Cross-Device Sync）

**Created**: 2026-08-15
**Status**: Implemented（含变更轮次 1/2，真机验证通过）
**Input**: User description: "实现华为多端流转功能，还有鸿蒙设备之间实现同步功能"

## Overview

为 ArkPix（HarmonyOS Pixiv 第三方客户端）增加两项华为生态能力：

1. **多端流转（应用接续）**：用户在一台鸿蒙设备上浏览 Pixiv 内容时，可无缝切换到另一台鸿蒙设备继续浏览。对端设备恢复"当前页面 + 上下文参数"（例如插画详情页带 illustId、用户主页带 userId、主页恢复 Tab 位置）。
2. **设备间数据同步**：登录同一华为账号的多台鸿蒙设备之间，自动同步应用设置、屏蔽列表、EXIF 配置（合并规则/优先级/屏蔽标签）与浏览/搜索历史，保持多设备体验一致。收藏状态走 Pixiv 服务端，天然同步，不在本特性范围内。

同步技术路线采用**分布式数据对象**（内存实时同步，单对象 ≤500KB）：设置类小数据直接同步；历史类大数据做裁剪/分片处理。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 插画详情页跨设备流转 (Priority: P1)

用户在手机上浏览某张插画详情页，走到平板前，通过系统接续入口在平板上拉起 ArkPix，平板直接打开同一插画详情页（同一 illustId），手机端应用退出到后台。

**Why this priority**: 流转是本特性的核心诉求；详情页是用户停留时间最长、最有接续价值的页面，单独实现即可构成可用的 MVP。

**Independent Test**: 双端登录同一华为账号、开启"多设备协同 > 接续"，源端停留在某插画详情页，对端通过系统接续图标拉起应用，验证对端打开相同 illustId 的详情页。

**Acceptance Scenarios**:

1. **Given** 双端设备满足接续条件且源端停留在插画详情页（illustId=123456），**When** 用户在对端触发接续，**Then** 对端 ArkPix 启动后直接进入该插画详情页并正常加载图片与信息。
2. **Given** 源端停留在多页插画详情页，**When** 对端接续恢复，**Then** 对端详情页显示完整 pageCount，可正常进入多页查看器。
3. **Given** 对端设备未安装 ArkPix 或不满足接续条件，**When** 用户尝试接续，**Then** 系统侧不提供接续入口，应用无需处理（系统行为）。

---

### User Story 2 - 主页/用户主页/其他页面流转 (Priority: P2)

用户停留在主页（某个 Tab）、用户主页（userId）、排行榜、搜索等页面时发起接续，对端恢复对应页面与上下文参数；不可识别的页面状态回退到主页。

**Why this priority**: 扩展流转覆盖面，提升整体接续体验，但详情页（P1）已可独立交付核心价值。

**Independent Test**: 源端分别停留在主页第 N 个 Tab、某画师用户主页，对端接续后验证恢复到相同 Tab / 相同 userId 的用户主页。

**Acceptance Scenarios**:

1. **Given** 源端停留在主页的第 3 个 Tab（排行），**When** 对端接续，**Then** 对端打开主页并定位到排行 Tab。
2. **Given** 源端停留在某画师用户主页（userId=789），**When** 对端接续，**Then** 对端打开该画师用户主页。
3. **Given** 源端页面状态缺失或无法解析（例如查看器、设置子页等不纳入流转的页面），**When** 对端接续，**Then** 对端回退打开主页默认 Tab，不崩溃、不白屏。

---

### User Story 3 - 应用设置跨设备同步 (Priority: P2)

用户在设备 A 修改应用设置（网络模式、画质、防社死开关、下载并发数等），设备 B 上的 ArkPix 在联网且组网在线时自动应用相同设置。

**Why this priority**: 设置同步是"多设备一致体验"的基础，数据量小（远小于 500KB 上限），最适合分布式数据对象实时同步。

**Independent Test**: 双端组网在线，设备 A 修改防社死开关，设备 B 无需重启即在设置页看到相同开关状态，且详情页行为随之变化。

**Acceptance Scenarios**:

1. **Given** 双端在线且已加入同一同步会话，**When** 设备 A 修改任一 AppSettings 字段，**Then** 设备 B 在数秒内收到变更并持久化到本地，重启后仍生效。
2. **Given** 设备 B 离线，**When** 设备 A 修改设置后设备 B 重新上线，**Then** 设备 B 恢复在线后同步到最新设置（依赖分布式对象的在线恢复机制；若无法自动恢复则以本地为准，不强制合并）。
3. **Given** 双端同时修改同一字段，**When** 同步收敛，**Then** 系统按分布式对象默认策略收敛到一致状态，应用不崩溃（不保证特定一方胜出）。

---

### User Story 4 - 屏蔽列表与 EXIF 配置同步 (Priority: P3)

用户在设备 A 维护屏蔽词/屏蔽作者、EXIF 合并规则、EXIF 优先级、EXIF 屏蔽标签，设备 B 自动获得相同配置，保存图片时 EXIF 行为一致。

**Why this priority**: 这类配置维护成本高、跨设备一致性价值大，但使用频率低于设置项，列为 P3。

**Independent Test**: 设备 A 添加一条屏蔽词与一条 EXIF 合并规则，设备 B 打开 EXIF 标签管理页与屏蔽页可见相同内容，且列表过滤行为一致。

**Acceptance Scenarios**:

1. **Given** 双端在线，**When** 设备 A 添加/删除屏蔽项或 EXIF 合并规则，**Then** 设备 B 对应页面展示同步后的最新数据并持久化。
2. **Given** 同步数据总量接近单对象 500KB 上限，**When** 用户继续追加规则，**Then** 应用对同步载荷做裁剪/序列化控制，不触发同步失败崩溃，本地数据始终完整可用。

---

### User Story 5 - 浏览/搜索历史跨设备同步 (Priority: P3)

用户在设备 A 的浏览历史与搜索历史，在设备 B 的历史记录页可见（按时间合并去重），实现"换设备接着找图"。

**Why this priority**: 历史同步提升多设备体验，但数据量最大、同步频率最高，需裁剪策略（如仅同步最近 N 条/仅同步增量摘要），复杂度最高，列为 P3。

**Independent Test**: 设备 A 浏览若干插画并产生搜索记录，设备 B 打开历史记录页能看到这些条目（时间倒序、按 illustId/keyword 去重），点击可正常跳转。

**Acceptance Scenarios**:

1. **Given** 双端在线，**When** 设备 A 新增浏览/搜索历史，**Then** 设备 B 历史页（刷新后）可见对应条目，重复条目按既有去重规则合并。
2. **Given** 历史数据超过同步载荷上限，**When** 同步发生，**Then** 仅同步裁剪后的最近历史（默认最近 100 条浏览 + 50 条搜索），本地完整历史不受影响。
3. **Given** 对端收到历史同步数据，**When** 写入本地数据库，**Then** 走既有先删后插/分组去重逻辑，不产生重复展示。

---

### Edge Cases

- 对端设备未登录 Pixiv 账号时接续到需要登录的页面：按应用现有未登录流程回退登录页。
- 接续载荷超过 100KB 限制：仅传递页面类型 + 关键 ID 等轻量参数（设计约束，详情页数据由对端重新拉取）。
- 双端 ArkPix 版本不一致导致同步字段不识别：未知字段忽略，不崩溃。
- 分布式对象同步会话建立失败（未组网/未开协同）：应用功能完全不受影响的纯本地降级。
- 同步数据与本地数据冲突（如双端离线各自修改）：收敛到系统默认结果即可，本地持久化以最终同步结果为准。
- 多设备（>2）同时在线：遵循分布式对象"最多 3 设备协同"的系统约束，不额外做设备数管理。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 应用 MUST 启用 UIAbility 接续能力（continuable 配置 + 单实例启动模式），使系统识别本应用可迁移。
- **FR-002**: 源端 MUST 在接续回调中保存当前页面类型与上下文参数（详情页=illustId；用户主页=userId；主页=Tab 索引），载荷控制在 100KB 以内。
- **FR-003**: 对端 MUST 在启动/拉起回调中解析接续参数并恢复对应页面；参数缺失或非法时回退主页。
- **FR-004**: 系统 MUST 在应用启动时创建分布式数据对象并加入固定同步会话；会话建立失败时静默降级为纯本地运行。
- **FR-005**: 系统 MUST 同步 AppSettings 全量字段，对端收到变更后持久化到本地偏好存储并驱动 UI 刷新。
- **FR-006**: 系统 MUST 同步屏蔽列表与 EXIF 配置（exifMutedTags / exifMergedTags / exifTagPriority / 屏蔽词与屏蔽作者）。
- **FR-007**: 系统 MUST 同步裁剪后的浏览历史（最近 100 条）与搜索历史（最近 50 条），对端写入本地数据库时复用既有去重逻辑。
- **FR-008**: 本地数据变更 MUST 反向写入分布式对象（双向同步），避免仅单向覆盖。
- **FR-009**: 系统 MUST 控制单分布式对象载荷 ≤500KB，超出时对历史类数据做裁剪，设置类数据天然远小于上限。
- **FR-010**: 应用 MUST 兼容同步字段缺失/未知的对端版本数据，解析失败字段跳过不崩溃。
- **FR-011**: 系统 MUST NOT 同步账号凭证（access_token / refresh_token）与下载文件本体。
- **FR-012**: 系统 MUST NOT 在设备间同步浏览相关设置：pictureQuality、mangaQuality、previewQuality、detailQuality、fullScreenQuality、crossCount、isTopMode（不同设备屏幕尺寸/形态不同，上述字段保持设备本地）。downloadQuality 及其他非浏览字段仍同步。**本约束同时适用于分布式设备间同步通道与后端中继同步（Relay SyncService settings 域）两个通道**——任一通道的载荷均不得携带上述字段，下行应用侧收到残留字段时跳过不应用。
- **FR-013**: 近距离设备同步开关（deviceSyncEnabled）MUST 与后端中继同步开关（syncEnabled）保持独立；用户在系统权限弹窗授权 DISTRIBUTED_DATASYNC 后，应用 MUST 立即尝试加入同步会话并即时刷新状态显示（未开启/未授权/已加入会话），不得要求重启应用生效。
- **FR-014**: 接续恢复页面 MUST 保持可返回的页面栈：对端落地时先进入主页（含 tabIndex 恢复），再将目标页（详情页/用户主页）压入栈顶，用户按返回键可回到主页而非直接退出应用。

### Key Entities

- **流转载荷（Continuation Payload）**: 页面类型枚举 + 上下文参数（illustId / userId / tabIndex）+ 载荷版本号，≤100KB。
- **同步设置对象（SyncedSettings）**: AppSettings 全量可序列化字段 + 屏蔽列表 + EXIF 配置 + 更新时间戳。
- **同步历史对象（SyncedHistory）**: 裁剪后的浏览历史条目（illustId、标题、作者、时间戳）与搜索历史条目（keyword、search_type、时间戳）+ 更新时间戳。
- **同步会话（Sync Session）**: 固定 sessionId 标识的分布式对象同步关系，随应用进程生命周期建立/退出。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 满足系统接续条件时，100% 支持的页面（详情页/用户主页/主页）可在对端正确恢复；接续参数传递 < 100KB，接续恢复到目标页面 < 5 秒（不含网络拉取详情数据时间）。
- **SC-002**: 双端在线时，设置/屏蔽/EXIF 配置变更在 5 秒内反映到对端并持久化，重启对端应用后仍生效。
- **SC-003**: 历史同步在对端历史页可见率 ≥ 95%（裁剪范围内条目），且无重复条目展示。
- **SC-004**: 同步会话不可用时（未组网/未开协同），应用全部既有功能 100% 不受影响，无崩溃、无阻塞性报错。
- **SC-005**: 同步/接续相关代码不引入任何账号凭证外发行为（代码审查可验证）。

## Assumptions

- 双端设备登录同一华为账号、开启 WLAN/蓝牙与"多设备协同 > 接续"，且双端均安装 ArkPix（系统前置条件，应用不检测不引导）。
- API 12+ 无需申请 DISTRIBUTED_DATASYNC 权限（已核实官方文档）。
- 接续仅迁移"当前页面 + 上下文参数"，不迁移完整页面栈（已确认）。
- 同步采用分布式数据对象（内存实时同步 + save 持久化），历史类数据裁剪后同步（已确认技术路线）。
- 收藏状态由 Pixiv 服务端保证一致性，不在本特性范围。
- 账号凭证、下载文件、图片缓存不做跨设备同步。
- 冲突解决采用分布式对象系统默认策略，不做应用层合并算法（历史除外：历史按既有去重规则合并写入）。

## Open Questions

- 历史同步的具体裁剪窗口（默认最近 100 条浏览 + 50 条搜索）是否满足实际使用，需实机验证后调整。
- 双端离线各自修改设置的"最后写入胜出"结果是否符合用户直觉，暂接受系统默认行为。

## Change Log

### 2026-08-15 首轮实现后用户反馈变更（4 项）

1. **浏览设置排除同步（FR-012）**：画质 5 档 + 瀑布流列数 + 沉浸模式改为设备本地，不同设备屏幕尺寸不同。
2. **开关独立性确认 + 授权状态刷新 bug（FR-013）**：deviceSyncEnabled 独立开关维持现状（通用设置页"设备间同步"分组）；修复"授权后需重启才显示已加入会话"——授权回调后应立即入会话并刷新状态。
3. **接续返回栈修复（FR-014）**：原实现对端 replaceUrl 直达目标页导致栈只有一页、返回即退出；改为落地主页后 pushUrl 目标页。

### 2026-08-16 变更轮次 2：浏览设置排除范围扩展到 Relay 通道

用户真机反馈列数仍被同步。根因：变更轮次 1 仅排除了分布式通道，Relay SyncService settings 域（collectSettings 上行 / applySettings 下行）仍携带全部 7 个浏览字段。FR-012 语义扩展为**全通道排除**：Relay 上行移除 7 字段、下行移除对应应用分支（旧服务器残留数据天然跳过，无需迁移）。
