# Feature Specification: 查看器与用户主页修复 + 下载/收藏管理增强

**Created**: 2026-07-25
**Status**: Draft
**Input**: User description: "1、多p的大图模式无法横向翻页、也无法缩放图片(US4)；2、US7长按按标题触发可接受；3、用户页没做瀑布流，并且关注数、作品数显示错误（皆为0）；4、下载管理要有一键重试、一键清空失败任务等；5、我的收藏应该支持多种排序方式；6、下载图片应该支持检测图片是否已经被下载过了，避免被重复下载"

## Overview

本轮包含两类工作：(1) 修复上一轮升级经真机验证发现的两个缺陷——全屏图片查看器多 P 无法横向翻页且无法缩放、用户主页未接入瀑布流且关注数/作品数恒为 0；(2) 三项管理体验增强——下载管理批量操作（一键重试失败/清空失败/清空已完成）、我的收藏多种排序方式、下载前重复检测（弹窗确认避免重复下载）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 全屏查看器翻页与缩放修复 (Priority: P1)

用户在全屏查看器中浏览多 P 插画时：左右滑动可正常横向翻页（页码同步更新）；双指张合可缩放图片；双击可放大/还原；放大后可拖动查看局部，且放大状态下不会误触发翻页，还原后翻页恢复。即手势竞争问题彻底解决：未缩放时单指横滑归 Swiper 翻页，缩放后单指拖动归图片平移，双指任何时候归缩放。

**Why this priority**: 上一轮核心故事 US4 在真机上两项关键交互均失效，查看器处于不可用状态，是最高优先级缺陷。

**Independent Test**: 打开一幅 ≥3P 插画的全屏查看器：横滑翻页成功且页码变化；双指放大成功；放大后拖动查看；双击还原；还原后横滑翻页恢复。

**Acceptance Scenarios**:

1. **Given** 多 P 查看器、图片未缩放，**When** 用户单指横向滑动，**Then** 翻到上一页/下一页且页码指示更新
2. **Given** 查看器中图片，**When** 用户双指张合，**Then** 图片以 1~5 倍范围平滑缩放
3. **Given** 图片已放大，**When** 用户单指拖动，**Then** 图片平移查看局部且不触发翻页
4. **Given** 图片已放大，**When** 用户双击，**Then** 图片还原为适应屏幕，随后横滑翻页功能恢复
5. **Given** 图片未放大，**When** 用户双击，**Then** 图片放大到预设倍数

---

### User Story 2 - 用户主页瀑布流与统计数据修复 (Priority: P1)

用户打开任意作者主页：关注数、作品数显示真实数据（不再恒为 0）；作品列表与其他列表页一致使用真实宽高比瀑布流（公共卡片、含红心/多 P 角标、支持分页加载与长按菜单）。

**Why this priority**: 统计恒 0 是明确数据显示错误（根因已定位：接口响应中统计字段在 `profile` 对象内，当前仅解析了 `user` 对象）；用户主页是上一轮 US10 的遗留缺口。

**Independent Test**: 打开任一作者主页，关注数/作品数显示非 0 真实值；作品按宽高比瀑布流展示，上滑可加载更多。

**Acceptance Scenarios**:

1. **Given** 某作者主页，**When** 页面加载完成，**Then** 关注数与作品数显示接口返回的真实数值
2. **Given** 作者作品列表，**When** 页面渲染，**Then** 卡片按真实宽高比展示（与推荐页一致的卡片样式与角标）
3. **Given** 作品列表存在更多数据，**When** 用户上滑到底部，**Then** 自动加载下一页

---

### User Story 3 - 下载管理批量操作 (Priority: P2)

用户在下载管理页可执行批量操作：一键重试所有失败任务、一键清空失败任务记录、一键清空已完成任务记录；操作前有确认提示，操作后列表即时刷新并 toast 反馈。

**Why this priority**: 用户明确提出的管理效率需求，数据层（任务状态表）已就绪。

**Independent Test**: 制造若干失败/已完成任务，分别执行三个批量操作，任务列表状态正确变化。

**Acceptance Scenarios**:

1. **Given** 存在失败任务，**When** 用户点击"一键重试"并确认，**Then** 全部失败任务重新进入下载流程，状态变为下载中
2. **Given** 存在失败任务，**When** 用户点击"清空失败"并确认，**Then** 失败任务记录全部移除
3. **Given** 存在已完成任务，**When** 用户点击"清空已完成"并确认，**Then** 已完成记录全部移除（不删除已下载的图片文件）

---

### User Story 4 - 我的收藏多种排序 (Priority: P2)

用户在收藏页可切换排序方式：收藏时间新→旧（默认，即接口原始顺序）、收藏时间旧→新、图片上传时间新→旧、按收藏数（作品 bookmark 数）高→低。切换后当前已加载数据即时重排；新加载的分页数据追加后同样按当前排序规则插入。（说明：Pixiv 接口不支持服务端排序，排序作用于本地已加载数据。）

**Why this priority**: 用户明确需求；收藏页已在上一轮接入公共瀑布流，排序为容器/页面层增强。

**Independent Test**: 收藏页切换到"收藏时间旧→新"，列表顺序反转且新加载页遵守该顺序。

**Acceptance Scenarios**:

1. **Given** 收藏页已加载数据，**When** 用户切换排序方式，**Then** 已加载条目按新规则即时重排
2. **Given** 已选择某排序方式，**When** 加载下一页或切换公开/私密，**Then** 新数据按当前排序规则合并展示
3. **Given** 收藏页，**When** 重新进入，**Then** 排序方式恢复默认（不持久化）

---

### User Story 5 - 下载前重复检测 (Priority: P2)

用户触发任何下载（详情页保存当前页/全部页、查看器保存、卡片长按保存）时，系统先检测该插画该页是否已成功下载过（本地下载记录存在且文件仍在）：若是则弹窗提示"该图片已下载过"，用户选择"仍要下载"才重新下载，选择"取消"则中止；未下载过则直接下载。检测按插画 ID + 页码粒度。

**Why this priority**: 用户明确需求，避免重复下载浪费流量与相册空间。

**Independent Test**: 下载某插画第 1 页成功后，再次保存该页，弹出已下载确认框；选取消不重复下载，选确认则重新下载。

**Acceptance Scenarios**:

1. **Given** 某插画第 1 页已下载成功，**When** 用户再次保存该页，**Then** 弹出确认对话框，取消则不产生新下载
2. **Given** 已下载确认对话框，**When** 用户选择仍要下载，**Then** 重新执行下载流程
3. **Given** 下载记录存在但本地文件已被删除，**When** 用户保存该页，**Then** 不弹窗直接重新下载
4. **Given** "保存全部页"中包含部分已下载页，**When** 触发批量保存，**Then** 对已下载页统一弹一次确认（或按所选策略处理），未下载页正常下载

---

### Edge Cases

- 查看器单 P 插画：隐藏页码，横滑无响应但不影响缩放
- 查看器缩放到边界后继续张合：限幅 1~5，松手回弹
- 用户无作品/私密账号：作品区显示空态，统计仍正确显示
- 一键重试时任务对应插画信息缺失：跳过该条并计数提示
- 排序切换发生在分页加载中：排队至加载完成后重排
- 重复检测时数据库不可用：降级为直接下载

## Requirements *(mandatory)*

### Functional Requirements

**查看器修复**
- **FR-001**: 查看器 MUST 解决手势竞争：未缩放时单指横滑触发翻页；双指任何状态下触发缩放；放大后单指拖动平移且不翻页；双击在放大/还原间切换
- **FR-002**: 缩放 MUST 保持 1~5 倍限幅与边界钳制；还原后翻页功能 MUST 恢复

**用户主页修复**
- **FR-003**: 用户主页 MUST 正确解析并显示关注数与作品数（统计数据位于用户详情接口响应的 profile 对象）
- **FR-004**: 用户主页作品列表 MUST 接入公共瀑布流容器（真实宽高比、卡片角标、分页加载）

**下载管理**
- **FR-005**: 下载管理页 MUST 提供"一键重试全部失败任务"（含确认、逐条重下、状态刷新）
- **FR-006**: 下载管理页 MUST 提供"一键清空失败任务"与"一键清空已完成任务"（含确认，仅清记录不删文件）
- **FR-007**: 批量操作完成后 MUST toast 反馈处理数量

**收藏排序**
- **FR-008**: 收藏页 MUST 提供排序切换入口，支持：收藏时间新→旧（默认）、收藏时间旧→新、上传时间新→旧、收藏数高→低
- **FR-009**: 排序 MUST 即时作用于已加载数据，且后续分页/刷新数据遵守当前排序
- **FR-010**: 排序选择 MUST NOT 持久化（重进恢复默认）

**下载去重**
- **FR-011**: 所有下载入口 MUST 在下载前按 插画ID+页码 检测成功下载记录
- **FR-012**: 记录存在且文件存在时 MUST 弹窗确认（仍要下载/取消）；文件已删则直接重下
- **FR-013**: 批量保存（全部页）时 MUST 对命中页汇总一次性确认

### Key Entities

- **DownloadTask（下载任务）**: 插画 ID、页码、状态（downloading/completed/failed）、文件路径、时间戳——复用既有 DB 表
- **收藏排序规则**: 4 种本地比较规则（收藏序正/反、上传时间、收藏数），作用于 Illust 数组
- **用户统计（profile）**: total_follow_users、total_illusts 等，独立于 user 对象

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 多 P 查看器横滑翻页与双指缩放操作成功率 100%（真机连续 10 次操作无失效）
- **SC-002**: 任意作者主页关注数/作品数显示与接口数据一致（非 0 场景准确率 100%）
- **SC-003**: 三个下载批量操作各 1 次点击完成全部目标记录处理，处理数量反馈准确
- **SC-004**: 收藏页 4 种排序切换后顺序正确率 100%，分页数据遵守排序
- **SC-005**: 重复下载检测命中率 100%，确认取消后 0 次重复下载

## Assumptions

- Pixiv 收藏接口不支持服务端排序，排序仅作用于本地已加载数据（已向用户确认接受）
- "收藏时间"以接口返回顺序为准（接口天然按收藏时间新→旧），本地不存收藏时间戳
- 清空任务记录不删除已下载到相册/磁盘的图片文件
- 重复检测以数据库下载任务表 + 文件存在性为准，不校验相册副本
- 上一轮 US7（长按按标题触发）用户已接受，不在本轮范围

## Open Questions

- 无（排序方式、去重策略、批量操作范围均已与用户确认）
