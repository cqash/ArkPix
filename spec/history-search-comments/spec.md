# Feature Specification: 历史记录与导出、Token 导出、搜索扩展、详情页 PID 与评论区

**Status**: Draft

## Overview

为 ArkPix 补齐四组用户数据与浏览辅助能力：(1) 在设置中提供历史记录页（浏览历史 + 搜索历史）并支持两种格式导出；(2) 在账户组提供 token 导出（剪贴板复制 / JSON 文件，均带安全确认）；(3) 搜索支持纯数字 PID/UID 直达与作者名称搜索（插画/画师 Tab）；(4) 详情页展示 PID 并新增评论区入口（查看、发表、回复）。大量基础设施已就绪（history 表、评论拉取 API、用户搜索 API、Comment 模型），本特性主要是接线与补全。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 浏览/搜索历史记录页 (Priority: P1)

用户在设置页点击"历史记录"进入历史记录页，页面分"浏览历史"和"搜索历史"两个 Tab。浏览历史按时间倒序以网格展示看过的插画（缩略图 + 标题 + 作者），点击重新进入该作品详情页；支持清空全部。搜索历史 Tab 展示搜索关键词列表（含类型标识），点击关键词直接以该词再次搜索。浏览历史数据来自现有 `history` 表（详情页加载时已自动写入），无需新增记录机制。

**Why this priority**: 数据已在自动积累，用户当前完全无法访问，是"已有能力解锁"型最高性价比功能；也是历史导出的前置。

**Independent Test**: 打开若干作品详情后进入设置→历史记录，能看到对应条目并点击回到详情；清空后列表为空。

**Acceptance Scenarios**:

1. **Given** 用户此前浏览过 3 个作品详情，**When** 进入设置→历史记录→浏览历史 Tab，**Then** 按时间倒序看到这 3 个作品的缩略图、标题、作者
2. **Given** 浏览历史列表有数据，**When** 点击某条目，**Then** 跳转对应作品详情页
3. **Given** 浏览历史有数据，**When** 点击"清空"并确认，**Then** 列表清空且重启应用后仍为空
4. **Given** 用户此前搜索过关键词"初音"，**When** 切换到搜索历史 Tab，**Then** 看到"初音"条目；点击后以"初音"执行插画搜索
5. **Given** 无任何历史，**When** 打开历史记录页，**Then** 两个 Tab 均显示空态视图

---

### User Story 2 - 历史记录导出（JSON / PID 列表）(Priority: P2)

用户在历史记录页可导出浏览历史，导出时选择格式：JSON（含 illust_id、标题、作者、时间等完整字段，与 EXIF 标签导出一致走系统保存位置选择器）或纯文本 PID 列表（每行一个 PID，便于导入其他工具）。

**Why this priority**: 依赖 Story 1 的页面作为入口；导出是数据主权需求但使用频率低于查看。

**Independent Test**: 浏览若干作品后导出两种格式各一次，用文本编辑器验证 JSON 结构完整、PID 列表每行一个数字。

**Acceptance Scenarios**:

1. **Given** 浏览历史有 5 条记录，**When** 选择导出→JSON 格式并选定保存位置，**Then** 生成 JSON 文件，内容为含全部 5 条记录完整字段的数组
2. **Given** 浏览历史有 5 条记录，**When** 选择导出→PID 列表格式，**Then** 生成文本文件，恰好 5 行，每行一个作品 ID
3. **Given** 浏览历史为空，**When** 点击导出，**Then** 提示"暂无历史记录"，不弹出保存选择器

---

### User Story 3 - Token 导出（剪贴板 / 文件，带安全确认）(Priority: P2)

用户在设置→账户组找到"导出 Token"入口，点击后先看到安全警告确认弹窗（说明 token 等同于登录凭证、泄露风险），确认后选择"复制到剪贴板"或"导出为文件"。复制到剪贴板直接复制当前账号的 refresh token 并 toast 提示；导出为文件则通过系统保存位置选择器写出包含 refresh token 的 JSON 文件（含账号基本信息，便于识别）。

**Why this priority**: 满足跨客户端迁移需求（配合已有 TokenLoginPage 形成闭环）；敏感操作需确认，但实现量小。

**Independent Test**: 确认后复制，粘贴到任意文本框验证为 refresh token；导出文件后用文本编辑器验证 JSON 内容；取消确认弹窗则无任何动作。

**Acceptance Scenarios**:

1. **Given** 已登录，**When** 点击"导出 Token"并在警告弹窗点取消，**Then** 弹窗关闭，无复制/导出动作
2. **Given** 确认警告后选择"复制到剪贴板"，**When** 在任意输入框粘贴，**Then** 内容为当前账号 refresh token
3. **Given** 确认警告后选择"导出为文件"并选定位置，**Then** 生成 JSON 文件，包含 refresh token 及账号名/用户 ID 等识别字段
4. **Given** 未登录状态（无有效 token），**When** 点击"导出 Token"，**Then** 提示无可用 token

---

### User Story 4 - 搜索 PID/UID 直达与作者名称搜索 (Priority: P1)

用户在搜索页输入纯数字时，搜索建议区顶部出现两个直达入口："插画 ID 直达"（直接打开该 PID 的作品详情页）和"画师 ID 直达"（直接打开该 UID 的用户主页）；PID 不存在时详情页展示错误态。输入非数字文本（如作者名称）时，搜索结果页分"插画"和"画师"两个 Tab：插画 Tab 为现有关键词插画搜索；画师 Tab 调用用户搜索，展示用户列表（头像 + 名称 + 账号），点击进入用户主页。

**Why this priority**: 搜索是高频入口；数字直达是 Pixiv 用户刚需（从外部拿到一串 ID 时）；用户搜索 API 已就绪。

**Independent Test**: 输入一个有效 PID 点击直达进入对应详情；输入 UID 直达进入用户主页；输入作者名切到画师 Tab 看到用户列表并点击进入主页。

**Acceptance Scenarios**:

1. **Given** 搜索框输入纯数字（有效 PID），**When** 点击"插画 ID 直达"，**Then** 打开对应作品详情页
2. **Given** 搜索框输入纯数字（无效 PID），**When** 点击"插画 ID 直达"，**Then** 详情页显示错误/失败态而非崩溃
3. **Given** 搜索框输入纯数字，**When** 点击"画师 ID 直达"，**Then** 打开对应 UID 的用户主页
4. **Given** 搜索框输入作者名称并提交，**When** 结果页切到"画师"Tab，**Then** 显示匹配用户列表；点击某用户进入其用户主页
5. **Given** 搜索框输入非数字关键词，**When** 查看建议区，**Then** 不显示数字直达入口

---

### User Story 5 - 详情页展示 PID (Priority: P1)

作品详情页信息区展示该作品的 PID（如 "PID: 12345678"），长按 PID 复制到剪贴板并 toast 提示。

**Why this priority**: 一行展示性改动，成本低、与 Story 4 的 PID 直达形成呼应。

**Independent Test**: 打开任意作品详情，可见 PID；长按后粘贴验证内容一致。

**Acceptance Scenarios**:

1. **Given** 打开任意作品详情页，**When** 查看信息区，**Then** 能看到该作品的 PID
2. **Given** 详情页已展示 PID，**When** 长按 PID 文本，**Then** PID 被复制到剪贴板并出现 toast 提示

---

### User Story 6 - 评论区（查看 / 发表 / 回复）(Priority: P2)

详情页信息区新增"查看评论"入口，点击进入评论页。评论页按时间展示评论列表（头像、用户名、正文、时间），上拉分页加载更多；有回复的评论显示"查看回复"入口，点击进入该楼的回复列表页（回复条目显示"回复 @某人"前缀）。底部输入栏支持发表评论（140 字上限）；点击某条评论的"回复"后输入框指向该评论，发送即作为其回复。评论中的表情占位符按纯文本展示（不实现 emoji 图片映射）。

**Why this priority**: 社区互动核心功能，但发表依赖新增 POST 端点且有账号风控风险，排在只读能力之后；整体为独立页面可独立交付。

**Independent Test**: 打开有高评论量作品→进入评论页→分页加载→查看某楼回复→发表一条评论→对一条评论发表回复，均在页面上可见。

**Acceptance Scenarios**:

1. **Given** 打开任意作品详情页，**When** 点击"查看评论"，**Then** 进入评论页并展示首批评论
2. **Given** 评论数超过一页，**When** 上拉到底部，**Then** 自动加载下一页并追加
3. **Given** 某条评论有回复，**When** 点击"查看回复"，**Then** 进入回复列表页展示该楼回复，回复条目带"回复 @用户名"前缀
4. **Given** 在评论页输入文字（≤140 字）并发送，**When** 发送成功，**Then** 新评论出现在列表中，输入框清空
5. **Given** 点击某条评论的"回复"，**When** 输入内容并发送，**Then** 该内容作为此评论的回复提交，并能在其回复列表中看到
6. **Given** 输入超过 140 字，**When** 尝试继续输入/发送，**Then** 被限制在 140 字或发送时提示超限
7. **Given** 网络失败或接口报错，**When** 加载/发送评论失败，**Then** 显示友好错误提示，页面不崩溃

---

### Edge Cases

- 历史记录中的作品已被作者删除：点击条目进入详情页时展示错误态
- 导出时用户取消系统保存选择器：无任何写入、无错误提示（或轻提示）
- 剪贴板不可用/权限异常：toast 提示复制失败
- 数字直达的 PID 对应 R18 作品且账号未开启 R18：沿用详情页现有错误/限制表现
- 评论为空的作品：评论页展示空态
- 发表评论接口返回错误（限流/风控）：toast 展示错误信息，输入内容不丢失
- 搜索历史 Tab 的关键词类型：既有数据均为 illust 类型，点击后按插画搜索执行

## Requirements *(mandatory)*

### Functional Requirements

**历史记录**
- **FR-101**: 系统 MUST 在设置页提供"历史记录"入口，进入历史记录页
- **FR-102**: 历史记录页 MUST 分"浏览历史"与"搜索历史"两个 Tab
- **FR-103**: 浏览历史 Tab MUST 按时间倒序网格展示历史条目（缩略图、标题、作者），数据来自现有 history 表
- **FR-104**: 浏览历史条目点击 MUST 跳转对应作品详情页；MUST 支持清空全部（带确认）
- **FR-105**: 搜索历史 Tab MUST 展示搜索关键词列表，点击后以该词执行搜索
- **FR-106**: 系统 MUST 支持导出浏览历史为 JSON（完整字段）或纯文本 PID 列表（每行一个 ID），格式由用户在导出时选择，保存位置走系统文件选择器

**Token 导出**
- **FR-201**: 设置页账户组 MUST 提供"导出 Token"入口
- **FR-202**: 导出前 MUST 弹出安全警告确认（说明泄露风险），取消则终止
- **FR-203**: 确认后 MUST 支持复制当前账号 refresh token 到剪贴板
- **FR-204**: 确认后 MUST 支持导出含 refresh token 及账号识别信息（用户名、用户 ID）的 JSON 文件

**搜索扩展**
- **FR-301**: 搜索框输入为纯数字时，建议区 MUST 显示"插画 ID 直达"与"画师 ID 直达"入口，分别跳转作品详情页与用户主页
- **FR-302**: 搜索结果页 MUST 提供"插画"与"画师"两个 Tab；画师 Tab 展示匹配用户列表（头像、名称、账号），点击进入用户主页
- **FR-303**: 无效 ID 的直达 MUST 展示错误态而非崩溃

**详情页**
- **FR-401**: 详情页信息区 MUST 展示作品 PID，长按可复制并 toast 提示
- **FR-402**: 详情页 MUST 提供"查看评论"入口进入评论页

**评论区**
- **FR-501**: 评论页 MUST 展示评论列表（头像、用户名、正文、时间）并支持游标分页加载
- **FR-502**: 有回复的评论 MUST 提供"查看回复"入口，回复列表页中回复条目 MUST 标注被回复人
- **FR-503**: 用户 MUST 能发表评论，长度上限 140 字
- **FR-504**: 用户 MUST 能对指定评论发表回复
- **FR-505**: 加载/发送失败 MUST 给出友好提示，页面不崩溃，发送失败时输入内容不丢失
- **FR-506**: 评论中的表情占位符按纯文本展示（emoji 图片映射不在本期范围）

### Key Entities

- **浏览历史条目**：作品 ID、标题、缩略图 URL、作者名、浏览时间（现有 `history` 表，无需变更）
- **搜索历史条目**：关键词、搜索类型、时间（现有 `search_history` 表）
- **评论（Comment）**：评论 ID、父评论 ID、用户（头像/名称）、正文、时间（现有 `models/Comment.ets`，可复用/扩展）
- **导出文件**：历史 JSON（版本号 + 条目数组）；Token JSON（版本号 + 账号识别字段 + refresh token）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从设置页出发 2 次点击内可看到自己的浏览历史，条目加载 1 秒内完成（1000 条以内）
- **SC-002**: 用户 3 步内（入口→确认→选格式/位置）完成一次历史导出，导出文件内容 100% 完整
- **SC-003**: 输入有效 PID 后 2 次点击内到达对应作品详情页
- **SC-004**: 输入作者名后 2 次点击内看到画师搜索结果列表
- **SC-005**: 用户从详情页 1 次点击进入评论区，首屏评论 2 秒内展示（正常网络）
- **SC-006**: 发表/回复评论成功率 ≥95%（排除账号风控等服务端拒绝），失败时输入内容 100% 保留
- **SC-007**: Token 导出全流程必须经过 1 次明确安全确认，0 次绕过路径

## Assumptions

- 浏览历史记录机制沿用现有实现（详情页加载成功时写入 `history` 表，无容量上限、按作品 ID 去重），本期不新增上限或自动清理
- 历史导出仅针对浏览历史；搜索历史不导出（价值低，关键词含隐私可按需在页面内清空）
- Token 导出的 JSON 文件包含版本号、账号名、用户 ID、refresh token；不包含 access token（短命、无迁移价值）
- Token 导出入口始终可见（与 pixez 的 isMailAuthorized 限制不同），因为本应用仅 OAuth 登录
- 表情占位符（如 `(normal)`）按纯文本展示；评论贴图（stamp）本期按占位文本处理或不展示
- 搜索结果页"画师"Tab 的用户搜索沿用已有 `searchUsers` API
- 数字直达入口在输入为纯数字时出现，不区分位数（pixez 的 pixivision 入口不实现）
- 详情页 PID 长按复制采用与现有 tag 长按一致的风格（直接复制 + toast，不弹菜单）
- 评论回复入口采用 pixez 方案（进入独立回复列表页），不做嵌套缩进
- 评论区不做屏蔽/举报/翻译功能
