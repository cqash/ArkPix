# Feature Specification: 流式下载改造（Streaming Download）

**Created**: 2026-08-30  
**Status**: Draft  
**Input**: User description: "改流式下载"（针对下载超时/大文件/弱网失败问题）

## Overview

当前图片下载使用 `http.request` + `ARRAY_BUFFER` 整图内存缓冲：超过系统默认单次传输上限（5MB，API 23 起 50MB）直接报错 2300023，弱网停滞 30 秒即整任务失败，且无自动重试、无断点续传。本特性将 DownloadService 改造为流式下载（`requestInStream` + `dataReceive` 流式写盘），彻底解除文件大小上限；加入任务内自动重试与超时调整、断点续传，并在下载管理页显示实时进度，系统性解决大文件与弱网环境下的下载失败。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 流式下载核心 (Priority: P1) 🎯 MVP

下载任意大小的图片（含超过 5MB/50MB 的高分辨率原图、多页漫画）不再受单次传输大小上限限制，数据边下边写盘，不再整图缓冲在内存；下载过程中产出实时进度（已下载字节数/总字节数）。

**Why this priority**: 这是"大文件总是失败"的根因修复，是其余故事（重试/续传/进度显示）的地基，仅交付此故事即可解决大文件下载失败。

**Independent Test**: 下载一张 >5MB 的原图（或弱网环境下任意图），下载成功且下载管理页任务最终状态为 completed。

**Acceptance Scenarios**:

1. **Given** 一张响应体超过 5MB 的原图，**When** 发起下载，**Then** 下载成功落盘，文件完整可打开，不再出现大小上限错误。
2. **Given** 下载过程中，**When** 响应数据持续到达，**Then** 任务进度随已接收字节数实时推进，且内存占用不随文件大小线性增长。
3. **Given** 服务器返回非成功响应码或错误页，**When** 下载结束，**Then** 任务置为 failed 且不产出残缺成品文件（半成品仅存于临时区）。

---

### User Story 2 - 自动重试与超时调整 (Priority: P2)

单次传输失败（超时、连接中断、5xx 等可恢复错误）时任务在内部自动重试（指数退避，最多 2–3 次），全部失败才置为 failed；读取超时容忍度调大以适应弱网长时间停滞。

**Why this priority**: 弱网瞬时抖动是失败率偏高的第二根因；依赖 US1 的流式传输循环作为重试载体，可独立交付与演示。

**Independent Test**: 模拟一次中途断连后恢复网络，任务不人工干预自动完成；日志可见重试次数。

**Acceptance Scenarios**:

1. **Given** 下载途中网络中断 <重试窗口时长，**When** 网络恢复，**Then** 任务自动重试并最终成功，用户无感知。
2. **Given** 连续多次失败（超出重试上限），**When** 重试耗尽，**Then** 任务置 failed，toast 提示失败，行为与现状一致。
3. **Given** 弱网导致数据停滞超过原 30 秒但小于新阈值，**When** 停滞恢复，**Then** 下载继续而非失败。

---

### User Story 3 - 断点续传 (Priority: P2)

任务失败后（含应用重启后的失败任务重试），从已下载的字节数处继续传输（HTTP Range），不重新下载已完成部分；对不支持 Range 的上游（中继模式或图床不支持）自动回退整文件重下。

**Why this priority**: 大文件+弱网组合下显著降低重复流量与耗时；与 US2 的重试共享恢复路径。与 US2 同为 P2，两者可独立交付（重试不含续传也能工作，续传依赖 US1 的临时文件机制）。

**Independent Test**: 下载大图中断 → 重试该任务 → 观察请求带 Range 头且仅传输剩余字节，最终文件完整。

**Acceptance Scenarios**:

1. **Given** 一个 failed 任务存在已下载 N 字节的临时文件，**When** 重试该任务，**Then** 请求携带 `Range: bytes=N-`，仅接收剩余数据并追加写盘，最终文件与完整下载一致。
2. **Given** 上游不支持 Range（对 Range 请求返回 200 全量），**When** 续传被触发，**Then** 识别后丢弃旧临时文件改为整文件重下，结果仍正确。
3. **Given** 应用重启后存在 failed 任务与残留临时文件，**When** 用户重试全部失败任务，**Then** 临时文件可被识别并续传，不产生错乱。

---

### User Story 4 - 下载页实时进度显示 (Priority: P3)

下载管理页（DownloadPage）任务行在下载中显示实时百分比进度（0–100%），随流式接收推进刷新，不造成列表闪烁。

**Why this priority**: 纯体验增强，依赖 US1 的进度产出；DB 已有 progress 列与 UI 展示位，改造成本低。

**Independent Test**: 开始一个大文件下载，观察下载页该任务行百分比持续增长直至完成。

**Acceptance Scenarios**:

1. **Given** 任务处于 downloading，**When** 数据持续接收，**Then** 列表行进度百分比随之增长（刷新频率受控，不闪烁）。
2. **Given** 任务完成或失败，**When** 状态变更，**Then** 进度显示归位（完成 100%/失败行显示失败态），与现有一致。

---

### Edge Cases

- 响应无 Content-Length（如 chunked 或中继未透传）：进度无法算百分比时显示已下载量或不显示百分比，下载功能不受影响。
- 临时文件损坏/大小超过 Content-Length：视为不可续传，整文件重下。
- 多页作品批量下载 + 并发上限调度：流式与重试不改变既有并发调度语义（上限即时生效、进行中任务不受影响）。
- EXIF 嵌入流程：续传完成后再执行嵌入与落库，嵌入失败按现有降级路径处理。
- 应用重启后 DB 中 downloading/pending 按既有规则重置 failed；残留临时文件保留供续传，任务删除/清理时同步删除对应临时文件。
- GIF（不嵌 EXIF）与嵌 EXIF 格式共用同一流式落盘路径，仅 finalize 步骤不同。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 图片下载必须改为流式传输（边接收边写盘），解除单次请求 5MB/50MB 的大小上限，任意大小文件可下载。
- **FR-002**: 下载过程必须产出实时进度（已下载字节数，及有 Content-Length 时的百分比），并随任务状态持久化到既有 progress 字段。
- **FR-003**: 单次传输的可恢复失败必须触发任务内自动重试（指数退避，上限 2–3 次）；重试耗尽才置 failed。
- **FR-004**: 读取超时必须在现状基础上调大（弱网停滞容忍），具体阈值在实施阶段确定并记录。
- **FR-005**: 重试/重新下载时必须支持断点续传：存在可用临时文件时携带 Range 头从已下载字节处继续；上游不支持 Range 时回退整文件重下。
- **FR-006**: 下载管理页必须显示下载中任务的实时百分比进度，刷新不闪烁。
- **FR-007**: 流式改造不得改变既有并发调度（上限动态读取）、自动收藏、EXIF 嵌入、写图库双通道、toast 提示等业务语义。
- **FR-008**: 任务完成/失败/删除时临时文件的生命周期必须受控：完成转成品、失败保留供续传、删除任务时清理。

### Key Entities

- **下载任务（DownloadTask，既有）**：复用既有 DB 表与模型，progress 字段由"恒 0"升级为真实进度；不新增表。
- **临时文件（Partial File）**：按任务 ID 命名的下载中半成品，存于下载目录；其文件大小即断点续传的偏移依据，避免 DB 迁移。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 超过 5MB（及超过 50MB）的原图下载成功率达到与小图一致的水平（本地验证 100% 成功）。
- **SC-002**: 弱网单次中断场景下任务无需人工干预的自动恢复率 ≥ 90%（重试窗口内恢复网络即成功）。
- **SC-003**: 断点续传命中时重复传输流量为 0（仅传输剩余字节）。
- **SC-004**: 下载中任务的进度百分比在下载管理页可见且每 2 秒内至少刷新一次。
- **SC-005**: 下载峰值内存占用与文件大小解耦（不因大图出现整文件级内存缓冲）。

## Assumptions

- 本期仅改造 DownloadService；ImageCacheService（浏览缓存）保持现状。
- 自动重试仅针对可恢复错误（超时/断连/5xx）；401 等鉴权错误沿用既有拦截器语义。
- 进度刷新沿用 DownloadPage 既有 1.5s 轮询 + 任务变更事件机制，不新增推送通道。
- 断点续传偏移以临时文件实际大小为准，不新增 DB 列、不做表结构迁移。
- 中继（relay）模式下续传取决于上游对 Range 的支持，不支持时自动回退整文件重下即满足需求。
