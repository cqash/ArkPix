# 人工测试方案：pixez 交互全面对齐

**对应特性**: `spec/pixez-interaction-alignment/`（spec.md / plan.md / tasks.md）
**测试环境**: HarmonyOS 真机（含振动马达）为主；模拟器用于验证震动静默降级。
**通用前置**: 已构建并安装应用，已登录 Pixiv 账号，网络可用（推荐列表能正常出图）。

---

## US1 全局触觉反馈

### 前置条件
- 设置 → 通用 → 「触觉反馈」开关开启（默认开）。

### 操作步骤与预期结果

| # | 步骤 | 预期 |
|---|------|------|
| 1 | 首页点击任一插画卡片 | 感到一次轻微点感（selectionClick 级）并进入详情页 |
| 2 | 列表页长按任一插画卡片 | 感到一次重震（heavy 级）后触发保存 |
| 3 | 详情页单击收藏 FAB 收藏成功 | 感到一次中震（medium 级）并 toast「已收藏」 |
| 4 | 再次单击收藏 FAB 取消收藏 | 感到一次轻震（light 级）并 toast「已取消收藏」 |
| 5 | 底部 Tab 切换（推荐→动态） | 感到一次轻微点感（selectionClick 级） |
| 6 | 任一设置页切换 SwitchItem | 感到一次轻震（light 级） |
| 7 | 评论页发送评论成功 | 感到一次中震（medium 级） |
| 8 | 查看器（ImageViewerPage）点击保存 | 感到一次轻微点感（selectionClick 级） |
| 9 | 历史记录页「清空浏览历史」确认；下载管理「清空已完成」确认 | 确认分支触发一次重震（heavy 级） |
| 10 | 50ms 内快速连点卡片/Tab 多次 | 仅第一次震动生效，后续被节流跳过，无震动粘滞 |
| 11 | 设置 → 通用 关闭「触觉反馈」，重复步骤 1-9 | 全部触点无任何震动，功能正常 |
| 12 | 模拟器（无马达）或系统设置关闭振动后触发震动点 | 静默降级：不报错、不闪退、功能正常 |

## US2 插画卡片长按直接保存

### 前置条件
- 设置 → 下载 → 「长按保存前确认」关闭（默认关）；「下载时自动收藏」按需开启验证 AC5。

### 操作步骤与预期结果

| # | 步骤 | 预期 |
|---|------|------|
| 1 | 推荐列表长按一张单页作品卡片 | heavy 震动后直接入队下载并 toast「已加入下载任务」 |
| 2 | 长按一张多页作品卡片（角标 xP） | 全部页入队下载，toast「已加入 N 个下载任务」 |
| 3 | 长按一张此前已下载过的单页作品 | 弹「图片已下载」对话框（取消/仍要下载） |
| 4 | 长按一张部分页已下载的多页作品 | 弹「跳过已下载页 / 全部重新下载」对话框；两个分支分别验证 |
| 5 | 开启「长按保存前确认」后长按卡片 | 先弹确认框（单页=「保存该作品到本地？」，多页=「保存全部 N 页到本地？」），确认后才开始下载 |
| 6 | 开启「下载时自动收藏」，长按保存一张未收藏作品 | 下载入队后该作品自动收藏（星标变红） |
| 7 | 长按卡片不再出现旧的三项菜单（保存/收藏/屏蔽作者） | 旧菜单已移除；「屏蔽作者」在详情页画师行长按菜单中仍可达 |
| 8 | 详情页画师行长按 | heavy 震动后弹菜单：屏蔽该作者 / 复制 UID；分别验证 toast 与剪贴板内容 |

## US4 带标签收藏

### 前置条件
- 账号有历史收藏标签（无标签账号用于验证空态）。

### 操作步骤与预期结果

| # | 步骤 | 预期 |
|---|------|------|
| 1 | 详情页（未收藏作品）长按收藏 FAB | heavy 震动后弹出带标签收藏面板（底部弹层） |
| 2 | 面板中勾选 1-2 个标签，选「私密」，点确定 | 收藏成功（三态爱心变红）；pixiv 网页端可验证标签与可见性生效 |
| 3 | 面板中不选任何标签直接确定 | 等价普通公开收藏 |
| 4 | 面板中切换公开/私密 | 两个 chip 选中态互斥切换正常 |
| 5 | 已收藏作品长按收藏 FAB | 不弹面板（仅未收藏时响应）；单击取消收藏行为不变 |
| 6 | 列表卡片右上角星标：单击未收藏作品 | selectionClick 震动+快速收藏（变红）；再单击取消（light 震动） |
| 7 | 列表卡片星标长按（未收藏） | heavy 震动+弹同一标签面板，确认后 star(illust, restrict, tags) |
| 8 | 断网后打开标签面板 | 显示错误态「标签加载失败，点击重试」，可直接点确定以无标签方式收藏 |
| 9 | 无收藏标签的账号打开面板 | 显示「暂无收藏标签」提示，可正常确认收藏 |
| 10 | 点击面板外半透明遮罩 | 面板关闭，不产生收藏变更 |

## US9 任意列表入口的详情页滑动切换（R2）

- 详情页底部「相关作品」区至少有 2 个作品；历史记录页有多条浏览记录。

| # | 步骤 | 预期 |
|---|------|------|
| 1 | 详情页 A 滚到底，点击相关作品中任一个进入详情页 B | B 可左右滑动切换 A 的相关作品列表，初始定位在点击的那一幅 |

| 4 | 预取途中断网 | 尾部出现失败重试占位，恢复网络后点击可重试 |

## US11 下载管理页增强（R3）

### 前置条件
- 存在多条下载任务，覆盖 completed / downloading / pending / failed 四种状态（可先下载若干作品，再断网制造一条 failed 任务）。
- 其中至少一条 completed 任务对应的作品已下载完成且本地文件存在；另准备一条本地文件已被手动清理（文件管理器中删除 cacheDir/downloads 下对应文件）的 completed 任务。

### 操作步骤与预期结果

| # | 步骤 | 预期 |
|---|------|------|
| 1 | 打开设置 → 下载管理，观察任务行行首 | 每行行首显示 56vp 圆角缩略图：completed 且文件存在→本地图；本地文件被清理→自动回退网络图；网络图也失败→CachedImage 自带错误占位，无空白/闪退 |
| 2 | 删除某 completed 任务的本地文件后重新进入页面 | 该行缩略图经 onError 回退为网络图，无需手动刷新 |
| 3 | 点击任一任务行 | 跳转该作品详情页，且可左右滑动切换当前可见任务对应的作品序列（按 illust_id 去重、保持列表顺序）；滑到末尾显示 No More 占位 |
| 4 | 同一作品有多页任务（多行同 illust_id） | 滑动序列中该作品只出现一次；点击其任一页任务行，详情初始定位到该作品 |
| 5 | 点击 failed 任务行内的「重试」按钮 | 只触发重试（toast 已加入下载），不跳转详情页 |
| 6 | 在筛选 chips 上依次点「全部 / 进行中 / 已完成 / 失败」 | 列表即时过滤：进行中=pending+downloading；选中 chip 高亮蓝底（#0096FA）白字，未选中灰底 |
| 7 | 切到「失败」筛选，停留观察 10 秒（覆盖多次 1.5s 轮询） | 筛选不被打断、不跳回「全部」；若有任务状态流转进/出 failed，列表随轮询自然增删 |
| 8 | 筛选状态下点击顶部「重试失败」「清空失败」「清空已完成」按钮 | 语义不变，作用于全部任务（不受当前筛选影响），确认弹窗与 toast 正常 |
| 9 | 选择一个无匹配任务的筛选（如无 failed 时点「失败」） | 显示「无匹配任务」空态文案，列表区无残留行 |
| 10 | 缩略图加载期间快速上下滑动列表 | 各行缩略图状态互不串扰（TaskThumb 独立状态），无错行显示 |

## US22 详情页缓存优先渲染（R8）

### 前置条件

- 已登录，网络正常；从**列表入口**进入详情页（详情可左右滑动），R7 预取正常工作（US21 步骤 1~2 通过）。
- 可控网络开关（验证断网分支）。
- 设备上有浏览历史可回访的作品（设置 → 历史记录）。

### 操作步骤与预期结果

| # | 步骤 | 预期 |
|---|------|------|
| 1 | 从列表第 N 项进详情，等首屏出图后停留 2~3 秒（留给预取完成），滑到相邻作品 | 详情与首图**立即显示，无整页转圈**（数据+首图全来自预取缓存，FR-046：缓存渲染不等待任何网络请求） |
| 2 | 步骤 1 滑入相邻作品后再停留数秒 | 收藏状态等新鲜数据**静默更新**（后台 refreshFromNetwork 完成后 UI 无感刷新，无 toast、无错误页） |
| 3 | 断网后滑向**已预取**的相邻作品 | 正常显示缓存内容（后台刷新静默失败，FR-048：不弹错误页/toast，内容不消失不回退转圈） |
| 4 | 断网状态下作品详情加载失败出现错误页，点"重试"后恢复网络再试 | 重试走原全量路径行为不变（错误页/404 快照兜底/成功加载均与改造前一致） |
| 5 | 正常网络下进入一个已加载过的详情页（如从浏览历史点击） | 详情**秒出**（DB 缓存命中先渲染），数秒后后台静默刷新（收藏态/作者信息对齐最新） |
| 6 | 详情页出现错误页时点重试（forceRefresh 强刷路径） | 行为与改造前完全一致（跳过缓存直取网络） |
| 7 | 滑入缓存命中的相邻作品，检查"设置 → 历史记录" | 该作品**进入浏览历史**（缓存渲染即写历史，FR-047：loadFromCache 本身不写，渲染点补偿写入；网络刷新成功再写幂等无重复） |
| 8 | 快速连滑 4~5 个作品 | 与 US21 步骤 3 一致：无请求堆积，代数作废机制不受影响（可用 `hdc hilog` 过滤 `Prefetch neighbor ok/aborted` 观察成功与中止日志） |

### 备注

- R8 根因背景：改造前 `store.load` 即使 DB 缓存命中仍 `await getIllustDetail` 网络往返后才返回——R7 预取只省了其后的图片下载，转圈主体正是那次 API 请求（"预加载没生效"的误判来源）。
- 缓存陈旧属预期：作品已被删除时缓存命中路径仍显示旧内容（后台 404 静默降级），强刷/重试才走快照兜底——符合 FR-048 静默降级语义。
- 预取日志说明：`Prefetch neighbor ok: <id> (cache)` = DB 缓存命中仅补首图；`(api)` = 走 API 后落缓存；`Prefetch neighbor aborted: <id> gen=<n>` = 快速连滑代数作废。
