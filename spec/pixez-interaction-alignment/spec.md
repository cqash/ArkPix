# Feature Specification: pixez 交互全面对齐（Pixez Interaction Alignment）——增量修订 R5

**Created**: 2026-09-17（R5 于同日追加）
**Status**: R5 修订（查看器底栏 pixez 化重排 + 分享图片）
**Input**: User feedback: "缩放查看器底部胶囊工具栏界面还要优化一下，查看pixez的截图；分享功能似乎没有分享到微信qq的选项，能不能增加？" → 选择"完全按 pixez 重排 + 查看器分享图片 + 不做加载百分比"

## Overview

R5 两部分：

1. **查看器底栏 pixez 化重排**：参照 pixez 截图，移除顶部工具栏（返回+SaveButton），所有操作集中为**底部一行极简图标**（复制图片 / 页码 / 返回 / 全屏 / 保存 / 分享 / HD），半透明悬浮、图标化。保存按钮保留为 SaveButton 安全控件（图标化但样式受平台约束）。既有功能逻辑（HD 切换/复制图片/全屏/保存/页码）不变，仅布局与视觉重排。
2. **查看器分享图片**：新增分享按钮，分享**当前页图片本身**（图片类型分享记录）。机制说明：系统分享面板中出现哪些目标应用（微信/QQ 等）由**目标应用自己声明**的接收类型决定，分享方无法指定添加；图片类型分享是微信/QQ 通常会声明接收的类型，比纯链接文本更可能让它们出现。详情页 ⋮ 菜单的"分享"保持分享链接不变。

**用户已确认的取舍**：完全按 pixez 截图重排（无顶栏）；查看器分享图片；不做中央加载百分比（图片加载链无进度回调，扩展成本高，用户明确不做）。

R1~R4 基线已完成并验证 PASS，R5 不改既有结论。

## User Scenarios & Testing *(mandatory)*

### User Story 18 - 查看器底栏 pixez 化 (Priority: P2)

图片查看器移除顶部工具栏，底部一行图标操作栏（对齐 pixez 截图）：复制图片图标、页码文本、返回图标、全屏图标、保存（SaveButton 图标化）、分享图标、HD 图标，半透明悬浮于图片上方、均匀分布。各按钮功能与 R4 完全一致（复制 pixelmap/全屏开关/SaveButton 授权保存/HD 切换）。页码仅多页显示逻辑不变。

**Independent Test**: 打开多页作品查看器 → 底部一行图标齐全可点；无顶栏；保存仍走 SaveButton 授权静默入册。

**Acceptance Scenarios**:

1. **Given** 查看器打开，**When** 查看界面，**Then** 底部一行图标（复制/页码/返回/全屏/保存/分享/HD），无顶部工具栏
2. **Given** 查看器，**When** 点各图标，**Then** 行为与 R4 底栏一致（返回 router.back、全屏切换状态栏、保存走 SaveButton 授权、HD 切换重载、复制图片 pixelmap 优先）
3. **Given** 防社死遮罩态，**When** 查看，**Then** 底栏可用性不被破坏

### User Story 19 - 查看器分享图片 (Priority: P2)

查看器底栏分享按钮：分享当前页图片（缓存文件以图片类型记录进 SharedData 拉起系统分享面板）。图片未缓存/获取失败时按钮半透明且点击 toast 提示（对齐 pixez"未缓存置灰"语义），不拉起空面板。

**Acceptance Scenarios**:

1. **Given** 图片已缓存，**When** 点分享，**Then** 拉起系统分享面板且内容为图片（支持接收图片的应用可见）
2. **Given** 图片未缓存，**When** 点分享，**Then** toast 提示且不拉面板
3. **Given** 详情页 ⋮ 菜单，**When** 点分享，**Then** 仍分享作品链接（行为不变）

---

### Edge Cases

- SaveButton 图标化须满足安全控件最小可见性约束（不可全透明/过小），样式调整在安全控件允许范围内
- HD 切换后分享：分享当前显示档位的图片（原图档优先取原图缓存，未缓存回退大图档缓存）
- GIF：分享静态缓存文件即可（pixez 同样按文件分享）
- 分享面板目标应用列表由系统决定，模拟器上可能无微信/QQ——属预期，不作为验收失败

- **FR-037**: 查看器分享按钮 MUST 分享当前页图片文件（图片类型分享记录）；未缓存时置灰+toast 不拉面板

## R6 增量（收藏页"已删除"占位卡误判修复）

**Input**: User feedback: "我的收藏顶部缩略图显示已删除，点进去图片实际还在，翻好几页才见正常图"
**Status**: R6（2026-09-17）

### User Story 20 - 收藏页已删除占位卡误判修复 (Priority: P1)

**缺陷**: `buildDeletedPlaceholders` 将"本地快照不在 API 收藏列表第一页"判为已删除。收藏超过一页时全部旧收藏被误报（占位卡堆满列表头部）；公开/私密 Tab 切换时另一 restrict 的快照也被误报。

**修复后行为**:
1. 快照候选 MUST 先按 `snapshot.restrict` 与当前 Tab（public/private）匹配过滤
2. 判删 MUST 经"全收藏列表分页走查"确认：后台复用 fetchNext 游标走完列表全部分页（上限 20 页），走查完整结束后仍缺席的快照才确认已删除
3. 确认删除的占位卡前置插入列表头部并刷新；走查失败/超上限 → 放弃插入（宁可漏报不可误报）
4. 占位卡在进页数秒后（走查完成时）出现，属预期延迟

**Acceptance**:
- 多页收藏（>1 页）打开收藏页：顶部不出现任何误报"已删除"卡，正常缩略图从顶部开始
- 真已被 Pixiv 删除的收藏作品仍显示占位卡
- 公开 Tab 不显示私密收藏的占位卡（反之亦然）
- 走查中断网：不插入任何占位卡，列表正常

**Functional Requirements**:
- **FR-040**: 快照判删 MUST 满足 restrict 匹配 + 全列表分页确认两条件
- **FR-041**: 走查失败或超 20 页上限 MUST 放弃插入占位卡
- **FR-042**: 确认删除的占位卡 MUST 仅出现一次（防 reload 循环：restrict 切换重置分类状态，单次会话内每 Tab 仅走查一次）

## R7 增量（详情页滑动相邻作品内容预取）

**Input**: User feedback: "详情页不是加了左右滑动的功能吗，好像没做对应的预缓存之类的优化性功能"
**Status**: R7（2026-09-18）

### User Story 21 - 滑动上下文相邻作品预取 (Priority: P2)

**现状缺陷**: 详情页壳 Swiper（cachedCount 1）只预建相邻 Pane 组件，`isActive` 门控使相邻作品的详情数据与首图均不预载——滑动到位后才开始 API 请求+图片下载，体验为空白/转圈。

**行为**:
1. 当前作品详情加载完成后，对相邻 ±1 个作品做预取（与 cachedCount 深度对齐）
2. 数据预取：先查 DB 详情缓存，未命中则 `getIllustDetail` 并写入 DB 缓存（与 `IllustDetailStore.load` 同一缓存路径，滑动激活时直接命中）
3. 首图预取：按当前用户 `detailQuality` 设置取 p0 URL，经 `prefetchCachedImage` 进图片缓存（档位一致确保激活时命中）
4. 仅列表入口（有 contextToken）的壳启用；单作品模式不预取

**Acceptance**:
- 从列表进详情，当前作品加载完成后静默预取左右相邻作品；滑过去详情与首图秒出（网络正常时）
- 快速连滑多个作品不产生请求堆积（代数作废机制）
- 预取不写浏览历史（红线：预取不走 `store.load()`）
- 预取失败静默，不影响当前作品展示

**Functional Requirements**:
- **FR-043**: 预取 MUST 复用 DB 详情缓存路径与 detailQuality 档位，确保激活时命中
- **FR-044**: 预取 MUST NOT 写浏览历史/产生任何用户可见副作用（toast/状态变更）
- **FR-045**: 快速滑动场景 MUST 有在途作废机制（代数计数）；已预取 id 以 Set 去重防重复请求

## R8 增量（详情页缓存优先渲染——让预取效果可见）

**Input**: User feedback: "预加载功能没生效，等了一分钟翻下一张还是要加载"（R7 验证后实测）
**Status**: R8（2026-09-18）

### User Story 22 - 详情页缓存优先渲染 (Priority: P1)

**根因**: `IllustDetailStore.load` 即使 DB 缓存命中，仍会 `await getIllustDetail` 网络往返后才返回渲染。R7 预取只省掉了 API 返回之后的图片下载，转圈主体正是那次 API 请求——预取生效但不可见。

**行为**:
1. `store.load` 拆分：`loadFromCache(id)`（纯 DB 缓存读取+收藏对账，无网络无副作用）与 `refreshFromNetwork(id)`（原网络路径：API→更新→落缓存→写历史）
2. Pane 激活：`forceRefresh` → 原全量路径；否则先 `loadFromCache`——命中**立即渲染**并**立即触发 onDetailLoaded**（相邻预取不等网络），再后台 `refreshFromNetwork` 静默刷新 UI
3. 缓存未命中 → 原路径不变（网络加载/404 快照兜底/错误页）
4. 历史写入：缓存命中渲染时即写（先删后插幂等，网络刷新成功再写无害）
5. 网络刷新失败（含作品已被删除的 404）：保留缓存渲染内容，静默降级，不弹错误页
6. R7 预取链路补 `console.info` 成功/中止日志（可观测性，后续诊断有据）

**Acceptance**:
- 列表进详情等首屏出图后，滑动到相邻作品**立即显示**（数据+首图全来自预取缓存，无转圈）；数秒后收藏态等新鲜数据静默更新
- 从浏览历史重访作品同样秒出
- 断网时滑动到已预取的相邻作品：正常显示缓存内容（后台刷新静默失败）
- 快速连滑：仍无请求堆积（R7 代数机制不变）
- 强刷入口（重试按钮）行为不变

**Functional Requirements**:
- **FR-046**: 缓存命中渲染 MUST NOT 等待任何网络请求；onDetailLoaded 必须在缓存渲染后立即触发
- **FR-047**: `loadFromCache` MUST NOT 写历史/产生网络请求；历史在缓存渲染时写入
- **FR-048**: 后台刷新失败 MUST 静默保留缓存内容（不弹错误页/toast）

# 附录：历史修订归档（R4/R3/R2，已完成）

## R4 Overview

R4 补齐详情页与缩放页对比 pixez 的剩余差异（pixez 文档 §2.2~2.5）：简介富文本展示（可点链接）、详情页顶栏溢出菜单、缩放页底栏增强（HD 切换/复制图片/全屏开关）、保存反馈文案四态对齐、信息区分辨率、相关作品滚到底自动加载。

**用户已确认的取舍**：简介用富文本+可点链接（非纯文本）；保存反馈用 toast 文案对齐（不做带 action 的自定义 banner，鸿蒙 toast 无 action 能力）；**翻译按钮与举报菜单项省略**（鸿蒙无对等的系统选词翻译 API，pixiv 无稳定举报接口）。

R1/R2/R3 基线已完成并验证 PASS，R4 不改既有结论。

## User Scenarios & Testing *(mandatory)*

### User Story 12 - 详情页简介展示 (Priority: P2)

作品详情页在 tag 胶囊区之后、评论入口之前展示作品简介：HTML 内容渲染为富文本（链接高亮可点、`<br>` 换行、其余标签剥离），点 pixiv 作品/画师链接应用内跳转（复用 PixivLinkParser），点外部链接打开系统浏览器。无简介时不渲染该区块。

**Independent Test**: 打开一个带简介（含 pixiv 链接与外部链接）的作品 → 简介正确渲染；点 pixiv 链接跳对应详情/画师页；点外部链接开浏览器。

**Acceptance Scenarios**:

1. **Given** 作品 caption 含 HTML 链接与换行，**When** 查看详情页，**Then** 渲染为可读富文本，无原始标签外露
2. **Given** 简介中 pixiv 作品链接，**When** 点击，**Then** 应用内跳对应详情页（pixiv://illusts 与 artworks URL 均支持）
3. **Given** 简介中外部 https 链接，**When** 点击，**Then** 打开系统浏览器
4. **Given** caption 为空，**When** 查看详情页，**Then** 简介区块不渲染、不留空白

### User Story 13 - 详情页顶栏与溢出菜单 (Priority: P2)

详情页顶部叠加返回按钮（左上）与 ⋮ 溢出菜单（右上，bindContextMenu）：分享（系统分享面板，内容=https://www.pixiv.net/artworks/{id}）、复制链接、复制文案（标题+简介纯文本）、画师信息（跳画师主页）、多图保存（打开选页弹窗）、屏蔽作者。菜单项与既有入口行为一致，不重复实现逻辑。

**Acceptance Scenarios**:

1. **Given** 详情页，**When** 点 ⋮ → 分享，**Then** 拉起系统分享面板且内容为作品链接
2. **Given** 详情页，**When** 点 ⋮ → 复制链接/复制文案，**Then** 剪贴板获得对应内容并 toast 确认
3. **Given** 详情页，**When** 点 ⋮ → 多图保存，**Then** 打开既有选页弹窗（与 FAB 长按一致）
4. **Given** 详情页，**When** 点顶栏返回，**Then** 返回上一页

### User Story 14 - 缩放页底栏增强 (Priority: P2)

图片查看器底部叠加工具栏：**HD 切换**（大图 ↔ 原图，切换当前页并重载，状态可见）、**复制图片**（写 pixelmap 到剪贴板，失败回退复制图片 URL 并 toast 说明）、**全屏开关**（隐藏/恢复系统状态栏）。既有顶部返回+SaveButton、底部页码、双击/双指缩放不变。

**Acceptance Scenarios**:

1. **Given** 查看器打开，**When** 点 HD 切换，**Then** 当前页切换为原图 URL 加载，再点切回大图
2. **Given** 图片已缓存/下载，**When** 点复制图片，**Then** 剪贴板获得图片（或 URL 回退+提示）
3. **Given** 查看器打开，**When** 点全屏开关，**Then** 状态栏隐藏；再点恢复

### User Story 15 - 保存反馈文案对齐 (Priority: P3)

所有下载入队入口反馈对齐 pixez 四态文案：JOIN="已加入下载队列"、INQUEUE=在途重复入队时提示"已在下载队列中"（新增检测）、ALREADY=保留现有 AlertDialog（跳过/重新下载）、SUCCESS=保留完成 toast。不做带 action 的自定义 banner（用户已确认）。

**Acceptance Scenarios**:

1. **Given** 某页下载在途，**When** 再次触发同页下载，**Then** toast"已在下载队列中"且不重复入队
2. **Given** 正常入队，**When** 触发下载，**Then** toast"已加入下载队列"

### User Story 16 - 分辨率与相关作品自动加载 (Priority: P3)

信息区统计行追加分辨率显示（宽×高，数据现成）；相关作品区滚到底自动加载下一批（替代/保留手动按钮由实现按 List onReachEnd 决定，优先自动加载）。

**Acceptance Scenarios**:

1. **Given** 详情页，**When** 查看信息区，**Then** 显示如 "1000×1500" 分辨率
2. **Given** 相关作品滚到底且有下一页，**When** 触底，**Then** 自动加载追加

### Edge Cases

- 简介 HTML 畸形/嵌套标签：解析器兜底为纯文本，不崩溃
- HD 切换在下载中页：仅影响查看器显示 URL，不影响下载（下载始终用原图）
- 复制图片时图片未缓存：先尝试加载解码；失败回退复制 URL
- 溢出菜单的"多图保存"在单页作品：打开选页弹窗（单页网格）或直接保存，行为与 FAB 长按一致
- 全屏开关：页面销毁/退出查看器时恢复状态栏，防泄漏

## Requirements *(mandatory)*

### Functional Requirements（R4 新增）

- **FR-029**: 详情页 MUST 展示简介富文本区块（tag 区后、评论入口前）：HTML→分段（文本/链接）解析，链接高亮；pixiv 链接经 PixivLinkParser 应用内跳转，外部链接开系统浏览器；空 caption 不渲染
- **FR-030**: 详情页 MUST 有顶栏（返回 + ⋮ 溢出菜单），菜单含：分享（系统分享面板，作品 URL）、复制链接、复制文案（标题+简介纯文本）、画师信息、多图保存（复用选页弹窗）、屏蔽作者（复用既有逻辑）
- **FR-031**: 缩放页 MUST 提供底栏：HD 切换（大图/原图，当前页生效）、复制图片（pixelmap 剪贴板优先，回退 URL+toast）、全屏开关（状态栏隐藏/恢复，页面销毁时恢复）
- **FR-032**: 下载反馈 MUST 四态文案对齐：JOIN/INQUEUE（新增在途检测 toast）/ALREADY（现有 AlertDialog）/SUCCESS（现有 toast）
- **FR-033**: 信息区 MUST 显示分辨率（宽×高）
- **FR-034**: 相关作品 MUST 支持滚到底自动加载下一批
- **FR-035**: 翻译按钮与举报菜单 MUST NOT 实现（用户确认排除）；缩放页"长按保存只存不收藏"因 SaveButton 安全控件约束不实现

## Success Criteria *(mandatory)*

### User Story 9 - 任意列表入口的详情页滑动切换 (Priority: P1)
